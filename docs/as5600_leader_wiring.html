AS5600 GELLO leader — recommended wiring

Single 3V3 rail from the USB-powered XIAO ESP32-C3 · TCA9548A mux · one AS5600 per channel · I²C @ 100 kHz

Build notes

  1. One 3V3 rail, from the XIAO. USB powers the XIAO; its 3V3 pin feeds the mux and every AS5600. Do not also feed an external supply (buck/bench) into 3V3 or 5V/VIN while USB is connected — on the XIAO C3 the 5V pin is tied to USB VBUS, so you'd back-feed the PC port. If you ever need an external rail, it's USB or external, never both.
  2. Run I²C at 100 kHz. 400 kHz was marginal on this harness and caused the register-read timeouts (the "sensors 4–6 missing" symptom). Set it as the firmware default (i2c_hz = 100000) so it survives a reset, not just the runtime i2c 100000 command.
  3. Main-bus pull-ups: 2.2–3.3 kΩ to 3V3 on SDA and SCL, placed between the XIAO and the mux. This is the segment that was under-pulled at 400 kHz. The AS5600 breakout boards usually carry their own channel-side pull-ups (4.7–10 kΩ, one set per channel); if you're using bare chips, add ~4.7 kΩ per channel to 3V3.
  4. Decoupling: 100 nF ceramic right at every AS5600 VCC↔GND, plus a bulk 100–470 µF (∥ 1 µF ceramic) across the 3V3 rail near the mux. (Helps noise margin; not what was blocking detection, but good practice once you can add them.)
  5. Mux config: TCA9548A A0/A1/A2 → GND (address 0x70), RST → 3V3 (or to a GPIO with -DPIN_MUX_RST if you want firmware bus-reset). Each AS5600 DIR → GND sets the count direction.
  6. Magnets are a separate matter. With clean reads at 100 kHz, several channels still report "too weak / too far" (AGC pegged at 128). That's genuine magnet strength/alignment, not wiring — center a diametric magnet 0.5–3 mm over each chip. It doesn't block teleop (angle still streams), but it's the next hardware follow-up.
